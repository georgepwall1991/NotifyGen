# Cycle 3 design: target-side explicit NotifyAlso dependencies

## Contract

`NotifyAlsoAttribute` keeps its existing source-side meaning by default:

```csharp
[NotifyAlso(nameof(FullName))]
private string _firstName;
```

Cycle 3 adds `NotifyFrom` for a target-side declaration:

```csharp
[NotifyAlso(nameof(FirstName), NotifyFrom = true)]
public string FullName => $"{FirstName} {LastName}";
```

The declaration means **when `FirstName` changes, also raise `FullName`**. The
source must be a property generated by NotifyGen in the same `[Notify]` type;
the target may be an ordinary computed property or another generated property.
Existing source-side declarations and their order remain unchanged. Multiple
declarations and transitive closure retain the cycle 1 ordering/deduplication
rules.

This is an explicit graph feature, not getter analysis. NotifyGen does not parse
computed-property expressions, inspect arbitrary methods, or discover object
paths. `NotifyFrom` is additive to the existing attribute and introduces no
runtime dependency or new attribute type.

## Generation

1. Extract eligible fields and incomplete partial properties as before.
2. Collect ordinary source-side edges from generated members.
3. Collect target-side edges from `NotifyAlso(NotifyFrom = true)` on properties or
generated members, reverse them into source → target edges, and merge them into
the source member's direct edge list.
4. Expand the merged explicit graph using the existing bounded, ordered,
deduplicated closure.
5. Emit `OnPropertyChanged("Target")` from the generated source setter exactly
as for a source-side declaration.

Target-side `NotifyOnSubPropertyChanged` is intentionally not supported in this
cycle. Child subscriptions remain source-side and direct; `NOTIFY012` warns
when a target-side attribute combines `NotifyFrom = true` with that option, and
no subscription is created on the computed target.

## Analyzer safety

- Unknown source/target names are reported through the existing `NOTIFY003`
  path, with the attribute location preserved.
- A target-side source is required to be a generated NotifyGen property; if the
  named source exists only as an ordinary hand-written property, the analyzer
  reports `NOTIFY011` and generation does not silently claim to wire it.
- Existing cycle detection (`NOTIFY008`) sees reversed target-side edges and
  reports cycles at the dependency attribute.
- Target-side declarations on ineligible fields do not create generated edges.

## Proof obligations

Tests must prove field and partial-property sources, ordinary and generated
targets, reverse-edge ordering, transitive closure/diamond deduplication,
unknown source diagnostics, non-generated-source `NOTIFY011`, cycle diagnostics,
and runtime `PropertyChanged` output. Generated source must compile with zero
errors and no new runtime references.
