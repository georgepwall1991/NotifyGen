# Cycle 2 research, evidence, and selection

Date of snapshot: 2026-08-08. NotifyGen is at `05a3b560c6fb0c605e0f6ffac035031084eb8bf3` / `v1.7.0` after cycle 1. This cycle re-checked competitor generator source and tests rather than README claims.

## CommunityToolkit.Mvvm

Source is pinned to `b135626dd54d33b8f05f2ff31591592c004aa848` (v8.4.2). Its generator reconstructs source attributes, including attributes that were written with `property:`, `get:`, or `set:` targets, before emitting them on generated properties/accessors: [attribute collection](https://github.com/CommunityToolkit/dotnet/blob/b135626dd54d33b8f05f2ff31591592c004aa848/src/CommunityToolkit.Mvvm.SourceGenerators/ComponentModel/ObservablePropertyGenerator.Execute.cs#L891-L984) and [emission](https://github.com/CommunityToolkit/dotnet/blob/b135626dd54d33b8f05f2ff31591592c004aa848/src/CommunityToolkit.Mvvm.SourceGenerators/ComponentModel/ObservablePropertyGenerator.Execute.cs#L1338-L1425). Its tests cover `Required`, `MinLength`, `MaxLength`, `JsonPropertyName`, `XmlIgnore`, and custom attributes: [metadata tests](https://github.com/CommunityToolkit/dotnet/blob/b135626dd54d33b8f2ff31591592c004aa848/tests/CommunityToolkit.Mvvm.UnitTests/Test_ObservablePropertyAttribute.cs#L860-L897) and [attribute fixtures](https://github.com/CommunityToolkit/dotnet/blob/b135626dd54d33b8f05f2ff31591592c004aa848/tests/CommunityToolkit.Mvvm.UnitTests/Test_ObservablePropertyAttribute.cs#L935-L1000).

The same project has an explicit nested-child notification proposal: [issue #1168](https://github.com/CommunityToolkit/dotnet/issues/1168) requests a `NotifyOnSubPropertyChanged` opt-in and describes subscribing/unsubscribing to the child `INotifyPropertyChanged`. Raw issue counts at the snapshot: **1 reaction** (`+1=1`, all other reaction types 0), **1 comment**; GitHub does not expose issue view counts. Independent demand is [Stack Overflow #78205281](https://stackoverflow.com/questions/78205281/maui-mvvm-notifypropertychangedfor-not-working-with-complex-object-and-its-child-property): raw score **1**, **1 answer**, **1,321 views**.

A separate metadata request, [issue #854](https://github.com/CommunityToolkit/dotnet/issues/854), has raw **0 reactions** and **4 comments** (views unavailable), while [issue #208](https://github.com/CommunityToolkit/dotnet/issues/208) has **3 reactions** (`+1=3`) and **17 comments**. The direct serialization/metadata question [Stack Overflow #75243887](https://stackoverflow.com/questions/75243887/use-primarykey-autoincrement-from-sqlite-in-net-maui-with-observableproperty) has raw score **2**, **1 answer**, and **1,313 views**. These are enough to select narrow property metadata forwarding, not a validation or serialization runtime.

## PropertyChanged.SourceGenerator

Source is pinned to `b51c349df7611edf0224645370fbf20a1d402eaa` (v1.1.2). It copies user property attributes through its generated-property model and emits them in [Generator.cs](https://github.com/canton7/PropertyChanged.SourceGenerator/blob/b51c349df7611edf0224645370fbf20a1d402eaa/src/PropertyChanged.SourceGenerator/Generator.cs#L277-L351). Its `PropertyAttributeTests` prove ordinary `XmlIgnore` forwarding and invalid-target handling: [tests](https://github.com/canton7/PropertyChanged.SourceGenerator/blob/b51c349df7611edf0224645370fbf20a1d402eaa/src/PropertyChanged.SourceGenerator.UnitTests/PropertyAttributeTests.cs#L13-L59). The clone has **188** NUnit test methods and **147** verified generated files; test execution was unavailable locally because its test target requires an absent .NET 7 arm64 runtime.

Its automatic getter dependency implementation recursively walks getter syntax in [Analyser_DependsOn.cs](https://github.com/canton7/PropertyChanged.SourceGenerator/blob/b51c349df7611edf0224645370fbf20a1d402eaa/src/PropertyChanged.SourceGenerator/Analysis/Analyser_DependsOn.cs#L102-L181), with **15** tests in [AutoDependsOnTests.cs](https://github.com/canton7/PropertyChanged.SourceGenerator/blob/b51c349df7611edf0224645370fbf20a1d402eaa/src/PropertyChanged.SourceGenerator.UnitTests/AutoDependsOnTests.cs#L197-L240). Its direct request [issue #36](https://github.com/canton7/PropertyChanged.SourceGenerator/issues/36) has **0 reactions** and **2 comments** (views unavailable), so automatic getter analysis is technically credible but evidence-thin here and is not selected.

## Fody.PropertyChanged

Source is pinned to `14a0870a7afcd44f334b4e122f3fb189106d16fa`. Its generated-property metadata and source/test fixtures establish the same attribute-forwarding and dependency space. Its typed post-change hook support is implemented in [OnChangedWalker.cs](https://github.com/Fody/PropertyChanged/blob/14a0870a7afcd44f334b4e122f3fb189106d16fa/PropertyChanged.Fody/OnChangedWalker.cs#L178-L202) and exercised by [typed hook fixtures/tests](https://github.com/Fody/PropertyChanged/blob/14a0870a7afcd44f334b4e122f3fb189106d16fa/Tests/AssemblyToProcessTests.cs#L332-L364). The historical request [issue #341](https://github.com/Fody/PropertyChanged/issues/341) has **1 `+1` reaction** and **5 comments**; it is recorded as an alternative, not selected this cycle.

Fody's open [issue #1109](https://github.com/Fody/PropertyChanged/issues/1109) asks for dependent-property fan-out when callers invoke `OnPropertyChanged` manually; raw counts are **0 reactions** and **2 comments**. Its source confirms dependencies are injected at setters, not the central invoker: [PropertyWeaver](https://github.com/Fody/PropertyChanged/blob/14a0870a7afcd44f334b4e122f3fb189106d16fa/PropertyChanged.Fody/PropertyWeaver.cs#L49-L61). This is useful comparator evidence but does not clear the demand bar for a larger central-dispatch redesign.

## MvvmGen

Source is pinned to `5f53e628746737f83b0a038135de65f7a3502cca`. Its property generator emits no copied property metadata: [PropertyGenerator.cs](https://github.com/thomasclaudiushuber/mvvmgen/blob/5f53e628746737f83b0a038135de65f7a3502cca/src/MvvmGen.SourceGenerators/Generators/PropertyGenerator.cs#L25-L98). Its open DataAnnotations/validation request [issue #5](https://github.com/thomasclaudiushuber/mvvmgen/issues/5) has **2 `+1` reactions**, **3 comments**, and no exposed view count. This supports forwarding user metadata, not generating `INotifyDataErrorInfo` or FluentValidation runtime behavior. The clone inventories **178** xUnit test methods, but its test command is blocked by the upstream Microsoft.Testing.Platform/VSTest mismatch on this machine.

## ReactiveUI.SourceGenerators

Source is pinned to `7e035e4266578294309966d34ee3bde1c29a6598`. It supports partial properties and access modifiers in [ReactiveGenerator.cs](https://github.com/reactiveui/ReactiveUI.SourceGenerators/blob/7e035e4266578294309966d34ee3bde1c29a6598/src/ReactiveUI.SourceGenerators.Roslyn/Reactive/ReactiveGenerator.cs#L24-L157). Its completed partial-property request [issue #121](https://github.com/reactiveui/ReactiveUI.SourceGenerators/issues/121) has **6 `+1` reactions** and **11 comments**, so it is already covered by NotifyGen 1.7 and is not a new candidate. ReactiveUI's runtime `ReactiveObject`/child-observable model requires a runtime dependency and is outside this generator's contract.

## Selection and rejected candidates

| Candidate | Evidence | Decision |
|---|---|---|
| Forward property-targetable source attributes to generated properties | SO #75243887: score **2**, **1 answer**, **1,313 views**; CommunityToolkit #208: **3 reactions**, **17 comments**; CommunityToolkit and PSG source/tests demonstrate the feature. | **Selected capability.** Narrow metadata forwarding; no validation/serialization runtime. |
| Opt-in child `INotifyPropertyChanged` bubbling | CommunityToolkit #1168: **1 `+1`**, **1 comment**; SO #78205281: score **1**, **1 answer**, **1,321 views**. | **Selected deepening.** Extend existing `[NotifyAlso]` with one boolean property; subscribe only when opted in and only to BCL `INotifyPropertyChanged`. |
| Typed `OnXChanged(oldValue, newValue)` hooks | Fody #341: **1 `+1`**, **5 comments**, plus pinned implementation/tests. | Evidence exists, but deferred to keep this cycle to exactly one deepening. |
| Automatic getter dependency inference | PSG #36: **0 reactions**, **2 comments**. Competitor implementation is mature, but demand is insufficient. | Dropped. |
| Central fan-out for manual `OnPropertyChanged` calls | Fody #1109: **0 reactions**, **2 comments**. | Dropped. |
| Validation, commands, messenger, DI, nested runtime graph discovery, or generated error storage | No qualifying demand for NotifyGen's constrained INPC surface; available signals are framework/runtime-specific or evidence-empty. | Dropped. |

Both selected items preserve source generation, ordinary `INotifyPropertyChanged`, zero external runtime dependencies, arbitrary base classes, and existing field/partial-property modes. No new attribute type is introduced; the deepening adds only `NotifyOnSubPropertyChanged` to the existing `[NotifyAlso]` attribute.
